# 整数规划
[TOC]

<!--more-->

## Takeaway

整数规划（Integer Programming, IP）要求部分或全部决策变量取整数值。

## Motivation

很多东西都是离散的，不是连续的。

与线性规划（LP）可在多项式时间求解不同，IP 通常是 **NP-hard**，可行域不再是连续凸集而是非凸离散点集。

## Core Mechanism

### Categorization

| 类型               | 说明                         |
| ------------------ | ---------------------------- |
| 纯整数规划 Pure IP | 全部变量必须取整数           |
| 混合整数规划 MIP   | 部分变量整数，其余连续       |
| 0-1 整数规划 BIP   | 所有变量只能取 0 或 1        |
| 一般整数规划       | 变量有整数上下界，不限于 0-1 |

### LP relaxation

这是求解中的重要一步

- LP relaxation: 先去掉整数约束然后求解得到最优解，LP relaxation 的作用是给出 bound

- Integrality Gap: 整数规划和 LP relaxation 之间的差距

  对于 minimization，常见定义是：

  $$
  \text{gap} = \frac{z_{\text{IP}}-z_{\text{LP}}}{z_{\text{IP}}}
  $$
  或者 ratio form：

  $$
  \frac{z_{\text{IP}}}{z_{\text{LP}}}
  $$
  如果 gap 很小，说明 LP relaxation 很紧；  
  如果 gap 很大，说明 LP relaxation 太松

### 0-1 变量建模

定义：
$$
x_j = \begin{cases}1 & \text{选择方案 }j\\0 & \text{否则}\end{cases}
$$

| 逻辑关系 | 建模 | 含义 |
|:--------:|:----|:----|
| **互斥（择一）** | $\sum_{j\in J} x_j \le 1$ | 至多选一个 |
| **多选（选 k 个）** | $\sum_{j\in J} x_j = k$ | 恰好选 k 个 |
| **条件约束（if A then B）** | $x_A \le x_B$ | 选 A 则必须选 B |

### Big-M 建模

**大M法（条件约束）**：使某个约束仅在条件成立时生效。引入 0-1 变量 $y$ 和充分大的常数 $M$：
$$
a^T x - b \le M(1 - y)
$$
$y=1 \Rightarrow a^T x \le b$（约束生效）；$y=0 \Rightarrow$ 右端为 $M$（约束失效）。

$M$ 应取"足够大但不至于过大"的值，太大会

- large M cons: weak relaxation + numerical issues

## Solution

### 割平面法

**割平面法（Cutting Plane / Gomory Cut）**. Gomory, 1958.

- Takeaway: 不断用新的 linear inequalities 收紧 LP relaxation，使它逐渐逼近真正的整数可行域的凸包

- Motivation

  真正决定整数规划最优值的凸集其实是：$\operatorname{conv}(S)$，integer hull，因此如果我们找到这个凸包，就是一个普通LP问题

- Core Mechanism:

  因此关键就在于每次如何构造新的线性约束：

  - Target: valid for all integer feasible points, violated by current fractional LP solution -- cutting plane

  **Gomory 割的推导**：

  设单纯形表中第 $i$ 行基变量 $x_{B_i}$ 的当前右端值 $b_i$ 为分数：
  $$
  x_{B_i} + \sum_{j} a_{ij} x_j = b_i
  $$

  将 $b_i$ 和 $a_{ij}$ 拆为整数部分与分数部分（$0 \le$ 分数部分 $< 1$）：
  $$
  b_i = \lfloor b_i\rfloor + f_i,\quad 0 < f_i < 1
  $$
  $$
  a_{ij} = \lfloor a_{ij}\rfloor + f_{ij},\quad 0 \le f_{ij} < 1
  $$

  代入整理得：
  $$
  x_{B_i} + \sum_j \lfloor a_{ij}\rfloor x_j - \lfloor b_i\rfloor = f_i - \sum_j f_{ij} x_j
  $$

  等式左边必为整数（变量均为整数），故右边也为整数。又因为 $f_i < 1$ 且 $\sum f_{ij}x_j \ge 0$，所以右边 $\le f_i < 1$。整数且 $<1$ 意味着必须 $\le 0$：
  $$
  f_i - \sum_j f_{ij} x_j \le 0 \quad\Longrightarrow\quad \sum_j f_{ij} x_j \ge f_i
  $$

  等价地化为标准形（加松弛变量 $s \ge 0$）：
  $$
  \sum_j (-f_{ij}) x_j + s = -f_i
  $$

  将此割加入单纯形表，因右端 $-f_i < 0$，用**对偶单纯形法**恢复可行性后继续迭代。

- Pipeline:

  ```mermaid
  graph TD
      A[求解 LP relaxation] --> B{解为整数?}
      B -- 是 --> C[当前解即 IP 最优解, 结束]
      B -- 否 --> D[选基变量为分数的行]
      D --> E[计算 Gomory 割: sum -f_ij x_j + s = -f_i]
      E --> F[加入单纯形表, 对偶单纯形法求解]
      F --> A
  ```

- Pros: 理论优雅

- Cons: 收敛可能很慢，割数量膨胀导致数值不稳定；对 MIP 不直接适用

### 分支定界法

**分支定界法（Branch and Bound, B&B）**. Land & Doig, 1960.

- Takeaway: 将可行域递归划分为子区域（分支），用 LP relaxation 的界来剪枝，跳过不可能包含最优解的子树。

- Core Mechanism:
  $$
  \text{relax} \rightarrow \text{bound} \rightarrow \text{branch} \rightarrow \text{prune}
  $$

  - 先求解LP relaxation
    
  - **分支（Branch）**：若当前 LP relaxation 的解 $x^*$ 中存在分数分量 $x_j = v_j$（非整数），则将问题分为两个子问题：
    - 左分支：$x_j \le \lfloor v_j\rfloor$
    - 右分支：$x_j \ge \lceil v_j\rceil$

  - **定界与剪枝（Bound & Prune）**：
    - 对 $\max$ 问题：当前最优整数解的目标值 = **下界** $z_{\text{incumbent}}$（incumbent 意为"现任最优"）
    - 任一节点的 LP relaxation 目标值 = 该子树的**上界**
    - **剪枝规则**：满足以下任一条件即可丢弃该节点：
      1. 节点的 LP 解已为整数（更新 incumbent）
      2. 对 $\max$，节点的上界 $\le$ 当前下界（不可能更好）
      3. 节点的 LP relaxation 无可行解

- Pipeline:

  ```mermaid
  graph TD
      A[根节点: 求解 LP relaxation] --> B{解为整数?}
      B -- 是 --> C[得到最优解, 结束]
      B -- 否 --> D[分支: 选分数变量 x_j, 分左右子节点]
      D --> E[依次求解各子节点 LP]
      E --> F{可否剪枝?}
      F -- 是 --> G[剪枝, 丢弃该节点]
      F -- 否 --> H[继续分支]
      H --> E
      G --> I{还有未处理节点?}
      I -- 是 --> E
      I -- 否 --> J[incumbent 即为最优解, 结束]
  ```

  **选分支变量的策略**：最大分数部分优先、最高优先级、或 strong branching（试探性求解几个候选分支，选效果最好的）。

- Pros: 直观鲁棒，剪枝效果好时大幅缩减搜索空间；可与割平面组合

- Cons: 最坏情况仍需指数级枚举；树深时内存开销大；节点选择策略影响效率

### Branch and Cut

- Takeaway: B&B+cutting plane 在节点处加割平面
- Pros: 现代求解器都使用

### 方法对比

| 方法 | 优点 | 缺点 |
|------|------|------|
| **割平面法** | 理论优雅，向单一 LP 逐步加割 | 收敛慢，割数量过多导致数值问题 |
| **分支定界法** | 直观鲁棒，好的界可大量剪枝 | 最坏指数复杂度，内存随树深增长 |
| **Branch & Cut** | 取两者之长——在节点处加割平面 | 实现复杂度高 |

现代商业求解器（CPLEX、Gurobi、SCIP）均采用 **branch-and-cut**：在 B&B 树的每个节点处结合 cutting plane，大幅提升效率。
